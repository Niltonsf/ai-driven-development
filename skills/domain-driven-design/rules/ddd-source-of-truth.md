# DDD rule: source of truth

One book, one PDF, nothing else.

## The source

`ddd-vlad-khononov.pdf`
Vlad Khononov, *Learning Domain-Driven Design: Aligning Software Architecture
and Business Strategy*, O'Reilly Media. 340 PDF pages. The copyright line on
PDF p.22 reads 2022, ISBN 978-1-098-10013-1. Never modified.

Locator to PDF page mapping: `../references/ddd-page-index.md`, generated by
`python3 tools/ddd_pdf.py index` from the PDF's own outline.

There is no "standard DDD" here, no Evans, no common practice. This book or a
halt.

## The normative range

A statement may enter a `ddd-*` skill, rule, card or command only if it can be
pointed at a PDF page inside **17-321**.

| Material | PDF pages | Status |
|---|---|---|
| Cover, copyright, table of contents, foreword | 1-16 | Not normative |
| Preface, Introduction, Parts I-IV, chapters 1-16, Closing Words, Appendix A, Appendix B | 17-321 | Normative |
| Bibliography | 323-324 | Citable only as evidence that a topic is deferred to another book |
| Index | 325-340 | Never citable |

## Pack-shared ranges

Four page groups carry material every skill needs. Any skill may cite them,
whatever its own `## Source` declares. `verify` reads this exact block:

```ddd-shared-ranges
21
293
303-304
309-313
315-321
```

| Pages | What they hold |
|---|---|
| 21 | The code conventions of the Preface: the samples are C#, the concepts are not limited to C# |
| 293 | Table E-1, the three types of subdomains restated in Closing Words |
| 303-304 | Appendix A's by-the-book rules for the CRM bounded context |
| 309-313 | Appendix A's discussion: ubiquitous language, subdomains, boundaries |
| 315-321 | Appendix B, the answer key `/ddd-exercise` grades against |

Every other page belongs to exactly one skill. A skill needing a page outside
its declared ranges plus these is either the wrong skill or the wrong question.
Route it; do not stretch it.

## What does not count

The closed exclusion list is `../references/ddd-not-in-this-book.md`. It carries
the evidence for each entry and the reason code each one halts with, because the
difference between `OUT_OF_SCOPE` and `UNDEFINED_IN_BOOK` is itself a finding.

Two entries decide most arguments:

- Repository as a pattern is `UNDEFINED_IN_BOOK`. The word appears as
  identifiers and as "mono-repository", and is never defined.
- Clean Architecture's principle families are `OUT_OF_SCOPE`, with one
  exception: the dependency inversion principle alone is in this book at p.152.

## Looking a claim up

```
python3 tools/ddd_pdf.py search "aggregate"     # which pages carry the term
python3 tools/ddd_pdf.py pages 185-193          # read those pages
python3 tools/ddd_pdf.py verify                 # prove the citation resolves
```

A claim that survives `verify` is a rule. A claim that does not is a halt.
