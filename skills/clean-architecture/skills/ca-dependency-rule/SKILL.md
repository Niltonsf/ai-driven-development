# CA Dependency Rule

## Source

Book scope: The Clean Architecture [CA ch.22 pp.161-166], DIP: The Dependency
Inversion Principle [CA ch.11 pp.83-86], Policy and Level [CA ch.19 pp.149-152].
This skill may cite no other chapter.

## Rules

1. Source code dependencies must point only inward, toward higher-level policies [CA ch.22 p.162]
2. Nothing in an inner circle can know anything at all about something in an outer circle, including the name of any function, class or variable declared there [CA ch.22 p.162]
3. Data formats declared in an outer circle are not used by an inner circle, especially formats generated by a framework [CA ch.22 p.162]
4. Level is the distance from the inputs and outputs; the farther a policy is from both, the higher its level [CA ch.19 p.150]
5. Low-level components are designed so that they depend on high-level components [CA ch.19 p.150]
6. Data flows and source code dependencies do not always point the same direction: dependencies are decoupled from data flow and coupled to level [CA ch.19 p.150]
7. An inner element that needs to call an outer one calls an output port interface in the inner circle, which the outer element implements [CA ch.22 p.164]
8. Dynamic polymorphism creates source code dependencies that oppose the flow of control, whichever direction the flow of control travels [CA ch.22 p.164]
9. The data that crosses a boundary is a simple data structure, always in the form most convenient for the inner circle [CA ch.22 pp.164-165]
10. Entity objects and database rows are not passed across a boundary [CA ch.22 pp.164-165]
11. The circles are schematic: there is no rule that says there must always be just these four [CA ch.22 p.164]
12. Source code dependencies refer only to abstractions, not to concretions [CA ch.11 p.83]
13. Stable background facilities such as the Java String class are tolerated as concrete dependencies [CA ch.11 p.83]
14. Violations that cannot be removed are gathered into a small number of concrete components, often called main [CA ch.11 p.85]

## Procedure

1. Name both parts, then rank them by distance from the inputs and outputs: the farther policy is the higher level [CA ch.19 p.150]
2. State the declared source code dependency: which element mentions the name of the other [CA ch.22 p.162]
3. Apply the direction table: the direction of those dependencies is based on the level of the components that they connect [CA ch.19 p.150]

| Condition | Action |
|---|---|
| The lower-level element names the higher-level one | Conforms: the dependency points inward toward higher-level policies [CA ch.22 p.162] |
| The higher-level element names a volatile lower-level one | Violates: nothing in an inner circle can know the name of something in an outer circle [CA ch.22 p.162] |
| The dependency is on a stable concrete facility such as the Java String class | Tolerated: changes to that class are very rare and tightly controlled [CA ch.11 p.83] |
| The two elements are at the same level | Same level: policies that change for the same reasons belong in the same component [CA ch.19 p.149] |
| anything else | HALT (`OUT_OF_SCOPE`) |

4. On a violation, prescribe the inversion: an interface declared in the inner element, implemented by the outer element, so the source code dependency opposes the flow of control [CA ch.22 p.164]
5. Apply the data table to whatever crosses: isolated, simple data structures are passed across the boundaries [CA ch.22 p.164]

| Condition | Action |
|---|---|
| A simple data structure crosses | Conforms: isolated simple data structures are passed across the boundaries [CA ch.22 pp.164-165] |
| An Entity object or a database row structure crosses | Violates: passing a row structure inward forces an inner circle to know about an outer circle [CA ch.22 pp.164-165] |
| A framework-generated data format crosses inward | Violates: data formats generated by a framework in an outer circle are not used by an inner circle [CA ch.22 p.162] |
| anything else | HALT (`OUT_OF_SCOPE`) |

6. Emit the output template below, one verdict per pair, with a citation on every claim per `../../rules/ca-citation.md`, writing the filled slots in Portuguese per `../../rules/ca-language.md`

## Halt conditions

| Trigger | Code |
|---|---|
| The request asks for a fixed number of layers or circles | `OUT_OF_SCOPE`, the circles are schematic |
| The request asks to name the layers of a folder tree | `OUT_OF_SCOPE`, routes to `ca-package-structure` |
| The request asks for code in a language outside the book | `CODE_STYLE_DIVERGENCE` |
| The codebase requires the inner element to name the outer one | `CONFLICT_WITH_PROJECT` |
| The level of an element cannot be settled from its distance to inputs and outputs | `AMBIGUOUS_IN_BOOK` |
| anything else | HALT (`OUT_OF_SCOPE`) |
